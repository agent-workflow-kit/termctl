# termctl: interface

Status: interface 0.1.0-design, 2026-10-30. Written before implementation (architecture §18.1). This document is the single normative source for termctl's rules; `docs/design.md`, the README and the architecture link to its headings instead of restating them.

termctl places commands in terminal windows. It is a Layer 1 primitive with one backend, tmux. It knows nothing about Claude, agents or the tools that call it: callers say *what* to open (a command, a cwd, a name, labels) and termctl's own configuration decides *where* ([Placement](#placement)).

## Concepts

### Managed panes

termctl manages **panes**. Each pane termctl opens is a *managed pane*, identified by a termctl id. `open` creates every managed pane as the only pane of a new tmux window, whose name is the pane's displayed name ([Names](#names)). A user may later add panes to that window; termctl never lists, renames, signals or closes a pane it did not open, and `close` removes only the managed pane ([`close`](#close)).

termctl keeps no database. Everything it knows about a managed pane is stored on the pane itself as tmux pane options ([Pane options](#pane-options)); tmux is the source of truth. A pane counts as managed only if its `@termctl_pane` equals its pane id, so inherited values are rejected unless they equal the pane's own id, which a value at window, session or global scope does only when deliberately set to name that pane ([Pane options](#pane-options)); such forgery by anything with socket access is a [residual risk](#residual-risks). When a pane or its whole tmux server is gone, its id is simply not found (exit 10).

### Identifiers

| Id | Grammar | Notes |
|---|---|---|
| termctl id | `^tc-[a-z2-7]{8}$` | Generated by `open`: 8 random base32 characters, checked against the managed panes of the server before the `pre-open` hooks run; on a collision `open` generates another. |
| tmux pane id | `%N` | Reported for humans and debugging only. tmux restarts numbering when its server restarts, so callers never store it. |
| tmux window id | `@N` | Same. |

Commands accept the full id or a unique prefix. Input is lower-cased; the `tc-` is optional; the rest must be 4 to 8 characters from `[a-z2-7]` (anything else, including a prefix longer than a full id, exits 2). A *full id* is 8 characters after normalization, with or without the `tc-`. A full id matches only a pane carrying exactly that id; a prefix matches every id that starts with it. A prefix that matches no managed pane exits 10; one that matches several exits 21 (`ambiguous`, with `candidates`). Two panes carrying the same full id (possible only if someone copied the options) are also ambiguous: exit 21, and termctl acts on neither. `close --force` takes only a full id (exit 2 for a prefix).

A caller that stores a termctl id also stores the `socket_path` from the same output and passes it back with `--socket` ([Server selection](#server-selection)).

### Names

A **name** is the friendly base name of a managed pane (for example `KEY-12` or `PR#42 review`). It is 1 to 64 Unicode code points of valid Unicode text (lone surrogates, such as undecodable bytes in an argument, are rejected), with no control characters (C0, DEL, C1; this includes tab and newline) and not containing `#[` (tmux would apply it as a status-line style). Any other text is accepted and displayed literally: termctl escapes it so that tmux interprets nothing in it ([tmux argument rules](#tmux-argument-rules)). A name that breaks these rules is rejected (exit 2); termctl never shortens or cleans a name. Two managed panes may have the same name; callers address panes by id.

Names are trusted input: callers build them from trusted data (for example a ticket key), never from third-party text such as an issue title or a review comment. The rules above stop tmux from interpreting a name, not a misleading name from being shown to the user.

Without `--name`, `open` uses the basename of the first argv element; if that is empty or not a valid name, `command`; with no argv, `shell`.

The **displayed name** (the tmux window name) is the stored marker text followed by the name while a marker is set and `marker_display` is `name`, and the name otherwise ([Markers](#markers)). termctl recomputes it from `@termctl_name`, `@termctl_marker_text` and the current `marker_display` whenever it changes a pane's name or marker. It turns off `automatic-rename` and `allow-rename` on every window it creates, so programs running in the pane cannot change the displayed name. termctl renames the window only while the pane is still in the window it was opened in (`#{window_id}` equals `@termctl_window`) and that window has exactly one pane; otherwise `rename`, `mark` and `unmark` update the pane options only and report `display_updated: false`.

The pane object's `display_name` is the window name tmux currently reports, read through tmux's format sanitizer (tab and newline become spaces) and reported as read. It is **untrusted**: anything that can reach the server's socket can rename a window. In a real run it is read after termctl's write. In a dry run it is the value termctl computes when the window would be renamed, and the current window name whenever `display_updated` would be false.

### Labels

Labels follow the design guide's multiset rules (section 9) and this grammar: a key matches `^[a-z0-9][a-z0-9_.-]{0,63}$`; a value is 0 to 256 characters from `[A-Za-z0-9._:/#@+=,-]`; a `key=value` argument is split at the first `=`, and an argument without `=` exits 2. A pane carries at most 32 labels (exit 2 beyond that; for `label add` this is checked after id resolution, so the failure is logged). A pane's labels are a set of pairs: a pair given twice (for example two equal `--label` on `open`) counts once, adding an identical pair is a no-op, and removing an absent pair is a no-op. termctl assigns no meaning to any label key; only the user's placement rules match on them.

Callers filter the labels they pass to this grammar and these limits; termctl rejects an invalid label (exit 2) and never cleans one.

### Markers

A **marker** is a named status shown on a managed pane, for example while the program in it waits for the user. Marker names match `^[a-z0-9][a-z0-9_-]{0,31}$` and are defined in config (`markers`); the built-in marker is `attention` with text `"🔔 "`. A marker's text follows the name rules, is 1 to 16 code points, and must not end in `#` (followed by a name starting with `[`, it would form `#[`). A pane has at most one marker; setting another replaces it.

termctl stores the marker's name and its text at the time it was set (`@termctl_marker`, `@termctl_marker_text`). `mark <id> M` changes nothing (`changed: false`: no log record, no bell) when M is already set with the text M has in the current config and, where termctl may rename the window ([Names](#names)), the displayed name equals the recomputed one; otherwise it rewrites both options and the displayed name. So callers may set a marker on every poll. A marker later removed from config stays stored and displayed until `unmark`, which always works.

`marker_display` controls where a marker shows; the pane options are set in both cases:

| Value | Displayed name |
|---|---|
| `name` (default) | marker text + name |
| `option` | name only; a user shows the marker through their own tmux status format ([Status format](#status-format)) |

A marker with `bell: true` also writes one BEL character to the pane's terminal (`#{pane_tty}`) when `mark` changes something on a running pane, which sets tmux's bell flag on the window. A failed write is a warning only. tmux ignores the bell on the window a client is currently viewing and may also ring the user's terminal, so `bell` defaults to `false`.

### Status format

With `marker_display: option`, the marker text is available to the user's tmux configuration as the pane option `@termctl_marker_text`, for example:

```text
set -g window-status-format '#{@termctl_marker_text}#I:#W#F'
```

## Server selection

Every command talks to exactly one tmux server, resolved in this order:

1. the global flag `--socket NAME|PATH`;
2. the environment variable `TERMCTL_SOCKET`, then config `socket`;
3. when the caller's environment has `TMUX` (termctl runs inside tmux), the server named there (its first comma-separated field is the socket path); a `TMUX` that is empty or starts with `,` counts as unset, as in tmux;
4. tmux's default socket, `default`.

A value containing `/` is a socket path; a relative one (allowed only for `--socket`) is resolved against the current directory. Any other value is a socket name, matching `^[A-Za-z0-9._-]{1,64}$` except `.` and `..`, and resolves to `<tmpdir>/tmux-<uid>/<name>` (the *default directory* form), using the real uid and the directory tmux itself would use as `<tmpdir>` (below). The config `socket` and `TERMCTL_SOCKET` must be a socket name or an absolute path. A socket path must be valid Unicode text (lone surrogates are rejected), must contain no control characters and no `,` (the first comma-separated field of `TMUX` is the socket path), must not end in `;`, must have a basename other than `.` and `..` (`/`, paths ending in `/`, and paths such as `/a/.`, `/a/..` or `rel/..` are rejected), and must be at most 100 bytes as given. A socket name contains no `,` by its grammar. Each violation exits 2 (`config_invalid` for config and environment, else `usage`); a `config_invalid` error carries `details.variable` for an environment variable and `details.key` for config.

**`<tmpdir>`** comes from the caller's `TMUX_TMPDIR` (read before the environment is filtered), as tmux reads it: the value is split on `:`, empty entries are skipped, and the first entry that is an existing directory (symlinks followed) is used; if there is none, or `TMUX_TMPDIR` is unset or empty, `<tmpdir>` is `/tmp`. Every entry must be an absolute path that is valid Unicode text and has no control characters and no `,` (termctl does not resolve a relative entry, which tmux would). An invalid `TMUX_TMPDIR` exits 2 (`config_invalid`, `details.variable: TMUX_TMPDIR`) when the server is a socket name or the default; when it is a socket path, an invalid `TMUX_TMPDIR` only means that no path is in default directory form. Its length is checked only as part of the resolved `socket_path`.

The resolved **`socket_path`** is canonical: the real path (symlinks resolved) of the deepest existing ancestor of the parent directory, joined with the remaining components of the parent directory and the socket's basename. Components are followed in order as the kernel would (a symlink is resolved, `..` goes up from a real directory); the walk stops at the first component that is missing, cannot be read or resolved, or is not a directory, and that component and the rest, `..` included, are kept verbatim. termctl uses it in every output, for the lock file name ([Audit and log](#audit-and-log)) and for the inside-tmux comparison of [`focus`](#focus). It must follow the socket path rules above, including at most 100 bytes (Unix socket paths have a platform limit; exit 2 otherwise). termctl always passes it to tmux as `-S <socket_path>`, never `-L`, and never scans other sockets. Every `--json` output that describes a managed pane carries `socket_path`.

Resolution has no side effects: it creates no directory and runs no tmux command.

**Socket safety.** tmux runs no permission checks for `-S` (spike F6), so termctl checks the socket before its first tmux operation ([Check order](#check-order)):

1. **Default directory form:** any socket path whose parent directory is `<tmpdir>/tmux-<uid>`, however it was obtained (a name, the default, `TMUX`, or a path passed back with `--socket` or set in config), including a given path whose parent reaches that directory through a symlinked ancestor or `..`. The parent must be owned by the real uid, not be a symlink, and have `mode & 0o027 == 0` (no group write, no access by others; tmux's own `-L` check rejects only access by others).
2. **Any other path** (explicit, or a `TMUX` path not in default directory form): the parent must be owned by the real uid or by root, not be a symlink, and not be writable by group or others (a sticky bit is no exception).
3. **Socket file:** an existing one must be a socket owned by the real uid.
4. **Ancestors** (every form): every existing directory from `/` down to the socket's parent must be owned by the real uid or by root, and one that is writable by group or others must have the sticky bit set (as `/tmp` does), so that no other user can replace a component of the path. The parent itself must also pass the stricter rule 1 or 2.
5. **Symlinks followed** (every form): every symlink followed while canonicalizing the given path must still be a symlink owned by the real uid or by root, and the real directory that contains it, with that directory's ancestors, must pass rule 4. A failure exits 12 with `details.path` naming the link or the failing directory.

A missing parent directory or socket file skips the checks that apply to it and means *no server* (below). A component that exists but is a symlink where one is refused, not a directory, part of a symlink loop, or cannot be checked fails the checks (exit 12); only a missing component means no server. A failed check exits 12 (`server_unavailable`) with a message naming the problem. `open` repeats the checks immediately before it starts a server or creates a session ([Open order](#open-order) step 5). The default directory is created only there, never in a dry run or by another command.

**No server** means the socket file or its parent directory does not exist, or connecting to the socket is refused (tmux reports no server running). Then `open` starts one ([Open order](#open-order)), `list` prints an empty list, `exists` exits 10 with its normal output, and every other command that talks to tmux exits 10 (`no_server`). `open` creates a missing parent directory only in the default directory form; for an explicit path whose parent is missing it exits 12 (`server_unavailable`), found in its tmux checks ([Open order](#open-order) step 3) and again before it starts a server (step 5). Any other connection error (for example permission denied) exits 12 (`server_unavailable`).

A `TMUX_TMPDIR` that differs between environments (for example set in a shell profile but not under cron) gives each a different default socket, and termctl run inside tmux on a non-default socket uses that server while cron uses the default; set `socket` in config (or the same `TMUX_TMPDIR` everywhere) when termctl runs from several environments.

## Placement

termctl decides where `open` puts a command. Placement is configured in termctl's config:

- `placements`: named placements. Each has `session` (a *session name*, `^[A-Za-z0-9_-]{1,64}$`), `target` (`window` or `pane`), and, for `target: pane`, `max_panes`, `layout` and `group_by`. The built-in `default` placement is `{session: termctl, target: window}`; a config entry named `default` is merged over it field by field. A field missing from any other configured placement is taken from the effective `default`.
- `rules`: an ordered list of `{match: {<label key>: <value>, ...}, placement: <name>}`. A rule matches when every pair in `match` is among the labels given to `open` (an empty `match` matches everything). The first matching rule wins; with no match, `default` is used.

Resolution for `open`:

1. `--placement NAME` selects that placement and skips the rules; otherwise the first matching rule, else `default`.
2. Per-field flags (`--session`, `--target`) override the selected placement's fields. `open --session` takes a session name; sessions that tmux reports (in outputs and the `list --session` filter) may be any non-empty string, since a user can rename a session, and are **untrusted** like `display_name` ([Names](#names)).
3. In this version only `target: window` is supported. `target: pane` and the fields `max_panes`, `layout` and `group_by` are part of the config schema; `open` and `placements` exit 2 (`code: not_supported`) when the placement they resolve uses them. Loading a config that contains them never fails, so other commands keep working.

A placement name matches `^[a-z0-9][a-z0-9_-]{0,63}$`. A rule naming an undefined placement is a config error (exit 2, `config_invalid`, at load); `--placement` naming one exits 2 (`usage`). `termctl placements` shows the effective placements and rules and, with `--label`, which rule and placement an `open` with those labels would use.

## Open order

`open` follows the [Check order](#check-order) with these steps:

1. **Usage checks** (exit 2; nothing is touched): flags; the name, label, marker, env-name, actor, decision-id, session-name and placement-name grammars; at most 32 labels, at most 32 `--env` and at most 32 `--decision-id`; no variable name given twice in `--env`; the cwd (`--cwd`, resolved against the caller's current directory, else that directory) must exist, be a directory, be valid Unicode text (lone surrogates are rejected), and contain no control characters and no `#[`; an absolute `--cwd` does not need a readable current directory; the socket ([Server selection](#server-selection)); an explicit `--` with no argv after it; an argv[0] containing `=` (`/usr/bin/env` would take it as a variable assignment); `--env PATH=...` without argv; `--override-escalation` without a TTY or a `human:` actor ([Hooks](#hooks)).
2. **Resolve**, without side effects: the server ([Server selection](#server-selection)); `tmux_bin`, once, to an absolute path on the caller's `PATH` ([Config](#config); exit 12, `tmux_missing`, reported in this step; `tmux -V` runs in step 3); the placement ([Placement](#placement); exit 2: `usage` for an undefined `--placement`, `not_supported`); the id. Then the **command check** (exit 12, `command_not_found`): an argv[0] containing `/` must be an executable regular file (a relative one is resolved against the cwd from step 1); any other argv[0] must be found on the `PATH` the command will get (the `--env PATH` value if given, else the filtered `PATH`, [Environment](#environment)); only its absolute entries are searched, so a command found only through an empty or relative entry, or with no `PATH` at all, is `command_not_found`. Finally the **size check** (exit 2): for the largest tmux invocation of steps 5 and 6, built for the new-session case, the UTF-8 lengths of its argv elements must sum to at most 12288 bytes (tmux rejects commands near 16 KB).
3. **tmux checks** (exit 12, [Check order](#check-order)); when the socket checks find no server and the socket is not in the default directory form, its parent directory must exist (exit 12, `server_unavailable`: termctl would not create it in step 5). Then the **id-collision check**: a read-only `list-panes -a`; if a managed pane already carries the id, termctl generates another and checks again. With no server running there is nothing to collide with. With `--dry-run`, termctl stops here: it prints the result ([`open`](#open)) and exits as a real run would, having run only read-only tmux queries (`tmux -V`, `has-session`, `list-panes`), no hooks, and changed nothing.
4. **`pre-open` hooks** ([Hooks](#hooks)), run once: a veto exits 11, an escalation exits 13; nothing is created.
5. **Server and session.** The hooks may have run long, so termctl first repeats the socket checks ([Server selection](#server-selection)) and probes again for a running server. Before every later tmux invocation of this step termctl runs the socket checks again: an unsafe socket exits 12 (`server_unavailable`), and a missing socket is no server (termctl never connects after the checks found none). When the probe finds no server, termctl makes the default directory ready (default directory form only): `mkdir` with mode 0700, never its parents, and whether that creates it or finds it there (`EEXIST`), all the socket checks again; for any other path the parent must exist (exit 12, `server_unavailable`). If a socket file is there by then (a stale one, or a server started meanwhile), termctl probes again and starts a server only if none answers. It then starts the server with the invocation that creates the session, prefixed with `set -s exit-unattached off \;` (a user's `exit-unattached on` would otherwise end a server that termctl starts without a client; the prefix runs after the user's config is loaded, spike F2). The prefix is used only when this probe found no server; termctl never changes the settings of a server it did not start (a server started by someone else between the probe and the start is a [residual risk](#residual-risks)). After every `new-session`, whether or not it started the server, termctl confirms with `has-session`. There are two creation paths:
   - **The placement's session exists** (exact match, `=<session>:`): one invocation runs `new-window -d -P -F '#{pane_id} #{window_id}' -t '=<session>:' -n <displayed name> -c <cwd>` with the placeholder or no command and, on the no-argv path only, the `-e` variables ([Environment](#environment)).
   - **It does not:** one invocation runs `new-session -d -P -F '#{pane_id} #{window_id}' -s <session> -n <displayed name> -c <cwd>` with the same command and `-e` variables, chained with `set -t '=<session>:' destroy-unattached off` (a user's global `destroy-unattached on` would otherwise remove the session before a second invocation could run) and, for each `-e` variable `K`, `set-environment -t '=<session>:' -u K`. If another caller created the session first (tmux reports a duplicate session), termctl takes the first path.

   If the session or the server is not there at `new-window` or at the confirmation (or a server appeared after the probe), termctl retries once after probing again, by whichever path the probe selects; if that fails too, exit 12 (`server_unavailable`). `open` never exits 10. Like every tmux invocation, these run with the filtered environment ([Environment](#environment)), which also becomes the server's environment when the invocation starts the server. If the server cannot be started or reached, exit 12 (`server_unavailable`).
6. **Pane.** The window is always created with `-d`, so it never becomes the session's current window; only step 8 selects it. Its name is the displayed name and its directory the resolved cwd. Every argument follows the [tmux argument rules](#tmux-argument-rules).
   - **With argv:** the window runs the placeholder `/usr/bin/env -- sleep 30`, which ends on its own if termctl dies; it gets no `-e` variables. In one further invocation termctl sets the pane options ([Pane options](#pane-options)), the window options `automatic-rename off` and `allow-rename off`, and the pane option `remain-on-exit` ([Command exit](#command-exit)), then replaces the placeholder with the real command (`respawn-pane -k`) in the resolved cwd with the `--env` variables as `-e`, and ends with the query of step 7. The command is always executed directly, never through a shell ([Command](#command)). Because the options are set before the real command starts, a command that exits at once cannot leave an untagged pane.
   - **Without argv:** the window is created with no command, so tmux starts its default shell as a login shell; the `--env` variables are passed as `-e` to `new-window` or `new-session` (step 5). termctl then sets the same options in a second invocation that ends with the query of step 7. A shell does not exit at once, so no placeholder is needed.

   The tagging invocation is guarded ([tmux argument rules](#tmux-argument-rules) rule 5) by the condition that the pane is untagged (empty `@termctl_pane`) and in the window step 5 reported.
7. **Record the process.** The query `display -p -t %N '#{pane_pid} #{pane_dead} #{pid}'` runs in the same invocation as step 6. termctl stores the pane's PID in `@termctl_pid` and that process's start time ([Liveness](#liveness)) in `@termctl_pid_start` only if `pane_dead` is 0 and the process's parent PID (Linux and WSL: field 4 of `/proc/<pid>/stat`; macOS: `ps -o ppid= -p <pid>`) is the server's PID (`#{pid}`), so the PID cannot belong to an unrelated process. Otherwise both stay empty and the output reports `pid: null`. If the query fails, termctl takes the state from a follow-up read; if that fails too, it reports `state: gone` with a warning and never reports a pane as running without reading it.
8. **Focus** if `--focus`, by the rules of [`focus`](#focus) without attaching (`open` never blocks); the outcome is reported in `focused`.
9. **`post-open` hooks**, a `log.jsonl` record, and the output. If the pane no longer exists at this point, the output reports `state: gone`, with `pane_id`, `window_id`, `display_name` and `session` the last known values.

If tmux fails during step 6 after the window was created, or the guard of step 6 does not match, termctl kills that pane by its exact pane id, guarded by the condition that the pane's `#{window_id}` is the window step 5 reported and its `@termctl_pane` is empty or its own pane id, and exits 12 (`tag_failed`); the log record has `result: error` and no `post-open` hook runs. A failure in step 7 or 8 does not undo the open: the output reports what is unknown and `open` exits 0.

### Command

`open -- <argv...>` runs argv directly, without a shell: termctl prefixes `/usr/bin/env --` so tmux always receives at least two arguments (tmux runs a single argument through `sh -c`). Shell features need an explicit `-- sh -c '...'`. Without argv the pane runs tmux's default shell as a login shell. Apart from the trailing `;` that termctl escapes ([tmux argument rules](#tmux-argument-rules)), tmux does not interpret argv elements, so they reach the program unchanged. Callers never put untrusted text in argv (architecture section 13.2 rule 2).

tmux takes a new pane's `PATH` from the environment of the tmux command that creates or respawns it and ignores `-e PATH` (spike C7). So for `--env PATH=X` termctl runs the command as `/usr/bin/env -- PATH=X <argv...>` (the assignment after `--`; spike G4): `env` sets `PATH` for the program, while the tmux invocation and a server it starts keep the filtered `PATH`. `--env PATH` without argv exits 2.

### Command exit

`--keep-on-exit never|failed|always` (config `keep_on_exit`, default `never`) controls what happens when the command exits. termctl sets it as the pane's `remain-on-exit` option (`off`, `failed`, `on`) and stores it in `@termctl_keep`.

| Value | Pane after exit |
|---|---|
| `never` | closed by tmux at once |
| `failed` | kept, as a dead pane, if the command exited non-zero or by a signal; closed otherwise |
| `always` | kept as a dead pane |

A closed pane takes its window with it when it is the window's last pane. A dead pane is still a managed pane: `show` and `list` report `state: dead` with `exit_status` or (tmux 3.3 and newer) `exit_signal`. Both can be null: on tmux 3.2 for a signal death, and on tmux 3.2 for a moment after any exit, before tmux closes a pane it does not keep. `close` closes a dead pane without `--force`. `list --dead` lists only dead panes.

## tmux argument rules

Every argument termctl passes to tmux is built by one function that applies these rules. tmux is always run as the absolute `tmux_bin` path resolved once per invocation ([Config](#config)).

1. **Separators.** tmux treats an argument that ends in `;` as a command separator in every position, including after `--` and in flag and option values, so the rest of the invocation would run as further tmux commands. termctl replaces the final `;` of every data argument with `\;`, which tmux turns back into `;`. Only termctl's own separators are a bare `;`. The `-S` value is not subject to this rule: socket paths ending in `;` are rejected ([Server selection](#server-selection)).
2. **Leading `-`.** For commands that take positional arguments, termctl puts `--` immediately before the first positional (`rename-window -t @W -- NAME`, `set -p -t %N -- @termctl_name VALUE`), never between two positionals. termctl gives a flag a value only where that command's flag takes one in tmux (for example `-c` of `new-window`, `new-session`, `respawn-pane` and `switch-client`, `-n` of `new-window` and `new-session`, `-s` of `new-session`), so tmux can never parse the value as further flags. A directory after `-c` is absolute, so it never starts with `-`. A window or session name after `-n` or `-s`, and a client name after `switch-client -c` (the `--client` grammar of [`focus`](#focus)), may start with `-`; tmux takes the element after the flag as the value whatever it starts with (spike E; for `-c`, `can't find client: -foo` on 3.2a and 3.5a).
3. **Format expansion.** tmux expands formats in the values of `-n`, `-c` and `-s` and in the `rename-window` name, and `#(...)` there runs a shell command. termctl doubles every run of `#` that is not followed by `[` in these values. Text containing `#[` (names, marker texts, the cwd) is rejected earlier (exit 2), and session names and ids have grammars without `#`.
4. **Literal positions.** argv after `--`, `-e` values and option values are not format-expanded; they need only rule 1.
5. **Guarded writes.** A pane id can be stale: hooks run, time passes, the server can restart and reuse `%N` for another pane. So after hooks or any delay termctl resolves the pane again by its termctl id, and runs every tmux operation that changes a managed pane (`kill-pane`, `rename-window`, `set -p`, `respawn-pane`, and the window options `set -w` of [Open order](#open-order) step 6) inside a guard:

   ```text
   if-shell -F -t %N -- '#{&&:#{==:#{@termctl_pane},#{pane_id}},#{==:#{@termctl_id},<id>}}' '<command>' 'display -p termctl-nomatch'
   ```

   The guard's `-t` is always a pane id. `<command>` is one of `kill-pane`, `rename-window`, `set -p` or `set -w` (`set-option -p` or `-w`, exactly one of the two, optionally with `-u`, `-q` or `-o`), `respawn-pane` (with `-k`, `-c` and `-e`) and `display -p` (`display-message -p`, for the query of [Open order](#open-order) step 7 and for `close --force`), with no other flags: never `-a` (all other panes), `-s` (another pane, or server options), `-g` (global options) or `-U`, and never itself an `if-shell`. It always names its target explicitly (without `-t` it would run against tmux's default target): the guard's own `%N` (for `set -w`, the window containing that pane), or, for `rename-window` and `set -w` only, `-t @W`, in which case the condition also requires `#{==:#{window_id},@W}`, so the window is the one containing the guarded pane. `set -p` sets only the [pane options](#pane-options) and `remain-on-exit`, and `set -w` only `automatic-rename` and `allow-rename`. `display` always has `-p` and prints only `#{pane_pid}`, `#{pane_dead}`, `#{pid}`, `#{pane_id}` and `#{window_id}`, separated by spaces. Its arguments follow rules 2 to 4 and are then each quoted: every run of the argument without a newline or byte 0xff is single-quoted, with every `'` written as `'\''`, and the runs are joined by `\n` for a newline and `\377` for byte 0xff, written outside the quotes (`'a'\n'b'` for `a`, newline, `b`), because tmux's parser drops a backslash before a newline and blanks and `#` comments after a newline even inside quotes, and treats byte 0xff as the end of its input even inside quotes, so the rest would run as commands. Every other byte, including invalid UTF-8, stays inside the quotes; every byte 0x01–0xff round-trips (NUL is refused). Inside the quotes rule 1 does not apply (spike F5). A `rename-window` guard also requires `#{==:#{window_id},#{@termctl_window}}` and `#{==:#{window_panes},1}` ([Names](#names)). If the pane is gone, tmux evaluates the condition as false (spike F5). Only an invocation that exits 0 is judged by its stdout; a non-zero exit (no server, a failing inner command) is a tmux failure, never a match. `termctl-nomatch` on stdout means the pane is no longer the one termctl resolved: exit 10 (`not_found`), except for `close`, which treats it as already closed ([`close`](#close)). The inner commands never print caller or tmux-controlled text (a guarded `display` prints only those ids and numbers), so no output of theirs can read as `termctl-nomatch`.

## Pane options

termctl stores these tmux pane options on every managed pane. Every one is always written at pane level (`set -p`); an empty value is written as `''`, never removed with `-u`, so a value from another scope cannot show through. They are internal to termctl but stable within a schema version; other programs may read them and must not write them.

| Option | Content | Grammar |
|---|---|---|
| `@termctl_v` | schema version of these options | `^1$` |
| `@termctl_pane` | the pane's own id at open; the ownership marker ([Managed panes](#managed-panes)) | `^%[0-9]+$` |
| `@termctl_window` | the id of the window the pane was opened in | `^@[0-9]+$` |
| `@termctl_id` | the termctl id | [Identifiers](#identifiers) |
| `@termctl_name` | the name | [Names](#names) |
| `@termctl_marker` | the marker name | marker name ([Markers](#markers)), or empty |
| `@termctl_marker_text` | the marker text stored when the marker was set | marker text ([Markers](#markers)), or empty |
| `@termctl_labels` | the labels | pairs sorted by code point, joined by single spaces (the label grammar excludes spaces), or empty |
| `@termctl_placement` | the resolved placement | placement name ([Placement](#placement)) |
| `@termctl_keep` | the keep-on-exit value | `never`, `failed` or `always` |
| `@termctl_created` | creation time | RFC 3339 UTC with millisecond precision |
| `@termctl_pid` | the command's PID | `^[1-9][0-9]{0,9}$`, or empty |
| `@termctl_pid_start` | that process's start time ([Liveness](#liveness)) | `^[0-9]{1,20}$`, or empty |

termctl reads all managed panes of a server with a single `list-panes -a` call. A `#{@...}` format also returns values inherited from the window, session or global scope (spike F4), so a pane is managed only if `#{@termctl_pane}` equals its `#{pane_id}`: inherited values are rejected unless they equal the pane's own id, which a value at window, session or global scope does only when deliberately set to name that pane (forgery, a [residual risk](#residual-risks)). termctl checks every `@termctl_*` value it reads against its grammar, as tmux prints it ([Residual risks](#residual-risks), forged control bytes); a pane with a missing or invalid value, or with a `@termctl_v` termctl does not know, is ignored with a warning (a `warning` log record).

Anyone who can reach the tmux server can change these options ([Residual risks](#residual-risks)).

A window linked into several sessions appears in `list-panes -a` once per session. termctl keeps one row per pane id, with `session` the first session tmux lists; `list --session` matches any session the window is linked into, and `focus` targets the pane id.

## Liveness

A managed pane is **running** when it exists and tmux does not report it dead (`#{pane_dead}` is 0); otherwise it is **dead**. `open` can also report **gone**, for a pane that closed before `open` returned.

The recorded PID is used only for signaling ([`close`](#close)): termctl signals a process only while its PID and start time equal `@termctl_pid` and `@termctl_pid_start`, and only if `@termctl_pid` equaled `#{pane_pid}` in the same `list-panes` row when `close` read the pane (steps 1 and 3 of [`close`](#close)). A recorded PID that fails this check is reported as `pid_mismatch: true` and is never signaled. The start time is an opaque per-host token: on Linux and WSL the clock ticks since boot from field 22 of `/proc/<pid>/stat`, on macOS the process start time in seconds since the epoch.

## Commands

All commands accept the [global flags](#global-flags), including `--socket`. Every command except `placements` talks to tmux: it can also exit 1 or 12 (`tmux_missing`, `tmux_too_old`, `server_unavailable`). The `--json` output of each command is described by `schemas/cli/<command>.json`, with a two-word command hyphenated (`label-add.json`, `label-remove.json`). The dry runs of `open` and `close` have their own schemas, `schemas/cli/<command>-dry-run.json`; every other dry run uses its command's schema with `dry_run: true`. Shared schemas: the pane object in `schemas/cli/pane.json`, the output of the pane-changing commands in `schemas/cli/pane-change.json`, the error object in `schemas/cli/error.json`, and the definitions shared by all schemas in `schemas/defs.json`.

### Check order

Every command checks in this order and stops at the first failure:

1. **Usage and config** (exit 2): flags, arguments, grammars, limits, the config file and the `TERMCTL_*` variables.
2. **Resolve the server** ([Server selection](#server-selection)): no side effects. A resolved `socket_path` that breaks the socket path rules, a `TMUX` whose first field is not a valid absolute socket path, or an invalid `TMUX_TMPDIR` used for a name or default source exits 2 here (`usage` for `--socket`, else `config_invalid`); `placements` never reaches this step.
3. **tmux checks**, before the command's first tmux operation (exit 12): `tmux_bin` resolves to an executable file (`tmux_missing`; `open` resolves it, and reports that failure, in step 2 of [Open order](#open-order)); `<tmux_bin> -V` runs (`tmux_missing`) and reports 3.2 or newer (`tmux_too_old`, [Errors](#errors)); the socket passes the safety checks (`server_unavailable`, [Server selection](#server-selection)).
4. **Id resolution** (exit 10 or 21; `no_server` when no server is running).
5. The command's own steps.

`placements` stops after step 1 and the placement resolution. `open` details its steps in [Open order](#open-order).

**Pane object.** `id`, `name`, `marker`, `marker_text`, `labels`, `placement`, `created` and `keep_on_exit` come from the [pane options](#pane-options), which anything with socket access can write, so `name`, `labels`, `marker`, `marker_text`, `placement` and `pid` are marked `x-untrusted` in the schema ([Residual risks](#residual-risks)); `display_name` is the current tmux window name ([Names](#names)); `session`, `pane_id` and `window_id` are tmux's; `socket_path` is the resolved server's ([Server selection](#server-selection)); `pid` is the recorded PID or null; `state` is `running` or `dead` ([Liveness](#liveness)); `exit_status` and `exit_signal` ([Command exit](#command-exit)) are never both set.

**Dead panes.** `show`, `rename`, `mark`, `unmark`, `label add`, `label remove` and `focus` work on dead panes as on running ones.

**Panes that vanish.** A pane can disappear between id resolution and a later tmux operation. tmux reporting that it cannot find the pane, window or session, or a guard printing `termctl-nomatch` ([tmux argument rules](#tmux-argument-rules) rule 5), exits 10 (`not_found`); `close` instead counts the pane as closed (exit 0).

**Dry runs.** `open`, `close`, `focus`, `rename`, `mark`, `unmark`, `label add` and `label remove` accept `--dry-run`: the command makes its checks (read-only tmux queries included) and exits as a real run would, but runs no hooks, changes nothing, writes no log or audit record, and prints what would change. For `rename`, `mark`, `unmark` and the label commands that is the pane object as it would be afterwards, with `dry_run: true` and `display_name` as in [Names](#names).

**Human output.** Each command's human-mode output is stated below; messages and warnings go to stderr. All human output, on stdout and stderr alike, is printed with each C0, DEL and C1 control character escaped as `\xNN` (its code point in two lowercase hex digits; line breaks between lines of output are kept), so no string from tmux (for example a window, session or client name), a hook (including `hook_stderr`), a pane option or the caller's own arguments echoed in a message (for example an unrecognized argument) can drive the user's terminal. This applies to every message, warning, usage line and help text, in `--json` mode too for what goes to stderr. `--json` output is not escaped this way; JSON string encoding already escapes C0 and DEL, and a consumer that displays a string escapes it itself. An argument that is not valid UTF-8 reaches termctl with each undecodable byte held as a lone surrogate (U+DC80 to U+DCFF, Python's surrogateescape); wherever termctl prints such a string, human output and `--json` alike, each of those is printed as the text `\xNN` (the byte in two lowercase hex digits) and any other lone surrogate as the text `\uXXXX` (four lowercase hex digits), so `--json` output never holds a lone surrogate and is valid for a strict JSON parser. Characters the output encoding cannot represent are written as backslash escapes (Python's `backslashreplace`).

### `open`

```text
termctl open [--name NAME] [--cwd DIR] [--env VAR=value]... [--label k=v]...
             [--placement NAME] [--session SESSION] [--target window|pane]
             [--keep-on-exit never|failed|always] [--focus] [--dry-run]
             [--actor ACTOR] [--decision-id ID]... [--override-escalation]
             [--hook NAME=CMD]... [-- ARGV...]
```

Opens a managed pane by the rules in [Open order](#open-order). `ARGV` must follow `--`, and everything after the first `--` is argv verbatim (later `--` and flags included); argv without `--`, or a `--` with nothing after it, exits 2. Human output: the id. `--json`: the pane object with `focused` and `decision_ids` added (`schemas/cli/open.json`); `state` may also be `gone`, and then `pid`, `exit_status` and `exit_signal` are null and `pane_id`, `window_id`, `display_name` and `session` are the last known values.

- `--cwd DIR`: a relative `DIR` is resolved against the caller's current directory.
- `--session SESSION`: a session name (`^[A-Za-z0-9_-]{1,64}$`, exit 2 otherwise); overrides the placement's session.
- `--env VAR=value` (repeatable, at most 32): sets a variable in the new pane's environment only ([Environment](#environment)). `VAR` matches `^[A-Za-z_][A-Za-z0-9_]*$`; the same `VAR` twice exits 2. `--env PATH=...` needs argv and also decides where argv[0] is looked up ([Command](#command)). **Values are not secret-safe**: they appear briefly in the tmux client's command line (visible to `ps`) and stay in the pane's environment. Never pass secrets this way.
- `--actor ACTOR` (`^(human|auto):[A-Za-z0-9._@-]{1,64}$`), `--decision-id ID` (repeatable, [Hooks](#hooks)): passed to the `pre-open` hooks and recorded in the log ([Audit and log](#audit-and-log)).
- `--override-escalation`: [Hooks](#hooks).
- `--hook NAME=CMD` (repeatable): [Hooks](#hooks).
- `--dry-run`: stops after step 3 of [Open order](#open-order) and prints what a real run would do. With `--json`: `{"dry_run", "id", "name", "socket_path", "tmux_version", "placement", "matched_rule", "session", "session_exists", "target", "cwd", "argv", "env_names", "labels", "keep_on_exit", "focus", "actor", "decision_ids", "override_escalation", "tmux_commands"}` (`schemas/cli/open-dry-run.json`). `id` is illustrative (a real run generates its own); `tmux_version` is the version `tmux -V` reported, null if it has no match; `matched_rule` is the index of the matching rule, null when none matched or `--placement` was given; `session_exists` is null when no server is running; `env_names` holds the `--env` names only; `decision_ids` holds the `--decision-id` values (no hooks run); `tmux_commands` lists each tmux invocation as argv, after the [tmux argument rules](#tmux-argument-rules), with `--env` values replaced by their names. Ids tmux has not assigned yet appear in those commands as the literal tokens `%NEW` and `@NEW`. Human output: the tmux commands, one per line.

Exit codes: 0; 1; 2; 11; 12 (`tmux_missing`, `tmux_too_old`, `server_unavailable`, `command_not_found`, `tag_failed`); 13.

### `show`

`termctl show <id>`: prints the pane object (`schemas/cli/show.json`, which is `schemas/cli/pane.json`). Human output: one line with the id, state, session and displayed name, separated by single spaces. Exit 0, 1, 2, 10, 12, 21.

### `exists`

`termctl exists <id>`: exit 0 if the managed pane exists (running or dead), 10 if not (including when no server is running). Human output: nothing. `--json`: `{"input", "id", "exists", "socket_path"}` (`schemas/cli/exists.json`) on both exit 0 and exit 10, the one non-zero exit that prints no error object ([Errors](#errors)); `id` is the full id, or null when nothing matched. Exit 0, 1, 2, 10, 12, 21.

### `list`

`termctl list [--label k=v]... [--session SESSION] [--dead]`: managed panes of the resolved server, ordered by `created`, then `id`. `--label` filters are ANDed; a filter matches when the pane has that pair. `--session` takes any non-empty string and matches any session the pane's window is linked into. `--dead` lists only dead panes. termctl applies these filters itself to its single `list-panes -a` read, never as tmux `-f` filters. Human output: one line per pane (id, state, session, displayed name, separated by single spaces, as for `show`). `--json`: `{"socket_path", "panes": [<pane object>...]}` (`schemas/cli/list.json`). No server running: an empty list, exit 0. Exit 0, 1, 2, 12.

### `rename`

`termctl rename <id> <name> [--dry-run]`: changes the name and recomputes the displayed name; a set marker is kept. The window is renamed only under the condition in [Names](#names). Renaming to the current name is a no-op (`changed: false`, no log record) when the displayed name already equals the recomputed one. Human output: the displayed name. `--json`: the pane object with `changed`, `display_updated` and `dry_run` (`schemas/cli/rename.json`, which is `schemas/cli/pane-change.json`). Exit 0, 1, 2, 10, 12 (`locked` too), 21.

### `mark`

`termctl mark <id> <marker> [--dry-run]`: sets the marker by the rules in [Markers](#markers) (a marker name not in config exits 2) and recomputes the displayed name, renaming the window only under the condition in [Names](#names); a marker with `bell: true` writes BEL when something changed on a running pane. Human output: the displayed name. `--json`: the pane object with `changed`, `display_updated` and `dry_run` (`schemas/cli/mark.json`, which is `schemas/cli/pane-change.json`). Exit 0, 1, 2, 10, 12 (`locked` too), 21.

### `unmark`

`termctl unmark <id> [--dry-run]`: clears the marker; the displayed name becomes the name, under the condition in [Names](#names). It changes nothing (`changed: false`, no log record, exit 0) when the pane has no marker and, where termctl may rename the window ([Names](#names)), the displayed name equals the name. Human output: the displayed name. `--json`: the pane object with `changed`, `display_updated` and `dry_run` (`schemas/cli/unmark.json`, which is `schemas/cli/pane-change.json`). Exit 0, 1, 2, 10, 12 (`locked` too), 21.

### `focus`

`termctl focus <id> [--client CLIENT] [--no-attach] [--dry-run]`: brings the managed pane into view. In order:

1. **Inside tmux on the same server** (the caller's `TMUX`, read before the environment is filtered, names a socket whose canonical path is the resolved `socket_path`) **and `TMUX_PANE` matches `^%[0-9]+$`:** termctl finds the session of the caller's own pane (`$TMUX_PANE`) and, among the clients attached to that session, picks one viewing the target pane's window if any, else the most recently active one (`client_activity`), and switches it. If no client is attached to that session, it continues at step 3; it never switches a client on another session here. With `TMUX_PANE` unset or not matching, termctl skips this step.
2. **Not inside tmux, stdin and stderr are terminals, and `--no-attach` is not given:** attach here with `<tmux_bin> -S <socket_path> attach -E -t '=<session>:<window_id>.<pane_id>'`. Without `--json`, termctl writes its log record and replaces itself with that command, run with the caller's unfiltered environment since it is the user's own terminal; `-E` keeps that environment out of the session ([Environment](#environment)). The exit status afterwards is tmux's, and `attach_failed` is reported only if the exec itself fails. With `--json`, termctl does not exec: it prints `action: attach` with `argv` set to `[<absolute tmux_bin>, "-S", <socket_path>, "attach", "-E", "-t", "=<session>:<window_id>.<pane_id>"]` and exits 0; the caller execs it with its own environment.
3. **Clients are attached to the server:** switches the most recently active client, preferring one attached to the pane's session. Inside tmux on a different server, termctl skips steps 1 and 2 and starts here.
4. **Otherwise:** exit 12, `no_client`; nothing changes.

`--client CLIENT` (`^/?[A-Za-z0-9_./-]{1,100}$`, exit 2 otherwise) skips steps 1 and 2 and switches that client (exit 10, `client_not_found`, if it is not attached); it may be combined with `--no-attach`, which then has no further effect. termctl always names the client it switches, passes `-E`, and targets the pane id (`switch-client -E -c CLIENT -t %N`), which selects the session, window and pane. tmux keeps one current window per session, so focusing a pane changes the current window for every client viewing that session. `--dry-run` reports the action termctl would take (`dry_run: true`) and never switches or attaches.

Human output: the client switched (nothing when attaching). `--json`: `{"id", "action", "client", "argv", "dry_run", "socket_path", "session", "window_id", "pane_id"}` (`schemas/cli/focus.json`); `action` is `switched` or `attach`; `client` is null and `argv` present only for `attach`. Exit 0, 1, 2, 10, 12 (`no_client`, `attach_failed`), 21.

### `close`

```text
termctl close <id> [--force] [--grace DURATION] [--actor ACTOR] [--decision-id ID]...
              [--override-escalation] [--hook NAME=CMD]... [--dry-run]
```

Closes a managed pane with `kill-pane -t %N`. The window closes with it when it is the window's last pane; panes a user added to the window are never killed.

`--force` is accepted only when stdin is a TTY or with `--actor human:<user>` (exit 2 otherwise), and only with a full id ([Identifiers](#identifiers)). Like `--override-escalation`, this gate is advisory ([Residual risks](#residual-risks)). `--grace` without `--force` exits 2.

1. **Check.** termctl reads the pane with `list-panes -a`. Its recorded PID counts only if `@termctl_pid` equals `#{pane_pid}` from the same row; if it does not, termctl reports `pid_mismatch: true` and sends no signal in this run. A running pane ([Liveness](#liveness)) without `--force` is refused: exit 20, `reason: running`; nothing changes and no hooks run. Automation never passes `--force` (design guide section 4.4); a human `--force` overrides `running`. termctl uses its own reason because the guide's `live` refusal, which nothing overrides, protects sessions, agents and worktrees, while closing a terminal pane is an ordinary human decision.
2. **`pre-close` hooks.** A veto exits 11 and an escalation exits 13, closing nothing.
3. **Re-check.** The hooks may run long, so termctl resolves the pane again by its id, applying the PID check of step 1 to the new row. If its state (running or dead) differs from step 1, termctl does nothing and exits 12 (`state_changed`); the caller may retry, which runs the hooks afresh. A pane that is gone, now or when the guarded `kill-pane` runs, counts as closed: exit 0, `post-close` hooks run, and the output reports `pane_closed: true` with `was_running` from step 1. If it was running at step 1 and `--force` was given, the signal sequence of step 5 still runs, but only for a recorded PID that passed the check of step 1, and checking only its start time (there is no `#{pane_pid}` to read); a PID that failed step 1 is never signaled, and a start-time mismatch reports `pid_mismatch: true` with `exited: null`.
4. **Dead pane:** guarded `kill-pane` ([tmux argument rules](#tmux-argument-rules) rule 5).
5. **Running pane with `--force`:** one guarded invocation reads the current `#{pane_pid}` and runs `kill-pane`; the pane's terminal closes and the kernel sends SIGHUP to the processes attached to it (spike F3). termctl then waits up to `--grace` (config `close_grace`, default `10s`) for the recorded process to exit, sends it SIGTERM, waits 5 seconds, sends SIGKILL, and waits up to 1 second for it to exit, stopping as soon as it has exited. It sends a signal only if the `#{pane_pid}` read at kill time equals `@termctl_pid` and the process's start time still equals `@termctl_pid_start` (checked before each signal); otherwise it sends nothing and reports `pid_mismatch: true` (the pane was respawned or the PID reused) with `exited: null`. With no recorded PID it sends nothing. Only the recorded process is signaled, by PID, never a process group; its children get only the kernel's SIGHUP. A process that survives SIGKILL is reported as `exited: false`; `close` still exits 0.

An id that is not found exits 10; callers treat 10 from `close` as "already closed". A `close --force` in which step 1 or step 3 saw a running pane writes an audit record whatever the outcome (closed, vetoed, escalated or failed), and so does `--override-escalation` ([Audit and log](#audit-and-log)). Human output: `closed <id>`. `--json`: `{"id", "pane_closed", "was_running", "forced", "signals_sent", "exited", "pid_mismatch", "decision_ids", "duration_ms", "socket_path"}` (`schemas/cli/close.json`): `forced` is whether `--force` was given; `signals_sent` lists only `SIGTERM` and `SIGKILL`, and `SIGKILL` only after `SIGTERM` (the SIGHUP is the kernel's); `exited` is whether the recorded process is gone at the end (true when there was none, null with `pid_mismatch`).

`--dry-run` makes the check of step 1 (exit 20 as a real run would, so a running pane is reported only with `forced: true`). With `--json` it prints `{"dry_run", "id", "state", "forced", "pid", "pid_mismatch", "signals_possible", "grace_ms", "socket_path", "actor", "decision_ids", "override_escalation"}` (`schemas/cli/close-dry-run.json`): `pid` is the recorded PID; `pid_mismatch` is whether it fails the `#{pane_pid}` check of step 1 or no longer has the recorded start time; `signals_possible` lists the signals a real run could send (empty for a dead pane, a mismatch or no recorded PID); `grace_ms` is the grace period in milliseconds; `decision_ids` holds the `--decision-id` values (no hooks run). Human output: one line with the state, the recorded PID, `pid_mismatch` and the possible signals.

`DURATION` is a non-negative integer without leading zeros followed by `ms`, `s` or `m` (a bare integer means seconds), at most `10m` (exit 2 otherwise).

Exit 0, 1, 2, 10, 11, 12, 13, 20, 21.

### `label add` / `label remove`

`termctl label add <id> k=v... [--dry-run]` and `termctl label remove <id> k=v... [--dry-run]` edit the pane's labels ([Labels](#labels)); at least one pair is required (exit 2). The pairs are contiguous: an option between two pairs (`label add <id> a=b --dry-run c=d`) exits 2. A call that changes nothing has `changed: false` and writes no log record. Human output: the pane's labels, space-separated. `--json`: the pane object with `changed`, `display_updated` (always false) and `dry_run` (`schemas/cli/label-add.json`, `schemas/cli/label-remove.json`: `schemas/cli/pane-change.json` with `display_updated: false`). Exit 0, 1, 2, 10, 12 (`locked` too), 21.

### `placements`

`termctl placements [--label k=v]...`: prints the effective placements (built-in and configured, merged; `origin` is `config` when any field comes from config, else `built-in`) and rules; with `--label`, also the rule that would match (`null` for none) and the placement `open` would use. Needs no tmux. Human output: one line per placement and rule, then the match. `--json`: `{"placements", "rules", "match"}` (`schemas/cli/placements.json`); `match` is null without `--label`, and otherwise an object with `labels` (the labels given), `rule` (the index of the matching rule, null for none) and `placement` (the placement `open` would use). Exit 0, 1, 2 (`not_supported` when the matched placement uses `target: pane` or its fields).

## Global flags

Global flags may come before or after the subcommand, never after `--`. A `--` may also precede positional arguments, for example `rename <id> -- -name`; a `--` before the subcommand (`termctl -- list`) exits 2, and a `--json` after that `--` is not a flag.

An option that takes a value always consumes the next token as its value, even one that begins with `-` (getopt semantics): `open --name -x -- ls` names the pane `-x`, and in `open --name --json -- ls` the name is `--json` and JSON output is not selected. `--opt=value` is equivalent. Only tokens before the first `--` that are not such values count as flags, for `--json` and `--version` as for the rest. A flag that takes no value rejects `=VALUE` (`--json=x`, `--version=x`, `-h=1`) as a usage error, exit 2.

| Flag | Meaning |
|---|---|
| `--json` | machine output (schemas in `schemas/cli/`); errors as `{"error": {...}}` on stdout ([Errors](#errors)), usage errors included |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | unexpected or internal error |
| 2 | usage error, invalid config, unsupported placement (`code: not_supported`) |
| 10 | id not found (also a pane that vanished mid-command), no server running, client not found |
| 11 | a pre-hook vetoed |
| 12 | expected failure; `code` is one of `tmux_missing`, `tmux_too_old`, `server_unavailable`, `command_not_found`, `tag_failed`, `no_client`, `attach_failed`, `locked`, `state_changed` |
| 13 | a pre-hook escalated (termctl has no pending store; the caller records the pending confirmation) |
| 20 | refused; `reason: running` |
| 21 | ambiguous id |

When SIGINT, or SIGTERM or SIGHUP while a hook runs, stops termctl, it kills the process group of the hook it is running, prints a one-line message to stderr (no error object) and exits 128 plus the signal number (130, 143, 129). A SIGTERM or SIGHUP the caller set to be ignored stays ignored.

## Errors

With `--json`, every non-zero exit prints `{"error": {...}}` on stdout (`schemas/cli/error.json`), except `exists` exiting 10, which prints its normal output; the error object is written first, then the message to stderr. Messages go to stderr in both modes, escaped (**Human output** in [Commands](#commands)); in human mode a usage error also prints the usage of the command it concerns. A failure to write stdout or stderr (a closed descriptor, a pipe with no reader) never changes the exit code.

| Field | Present |
|---|---|
| `code` | always; see the table below |
| `message` | always; for humans; termctl's own text, never hook output (a hook is named by its `cmd`) |
| `reason` | only with `refused`: `running` |
| `hook`, `hook_stderr` | only with `vetoed` and `escalated`: the `cmd` of the first hook that vetoed (else escalated), and its stderr, **untrusted**, cut to 4096 bytes at a UTF-8 character boundary. In human mode the stderr follows the message, each of its lines on a line of its own behind the fixed prefix `termctl: hook stderr:` and a space, escaped (a CR included), so no line of it can pass for one of termctl's |
| `decision_ids` | when there are any: the `--decision-id` values, then the ids returned by hooks ([Hooks](#hooks)) |
| `candidates` | only with `ambiguous`: the matching panes (`id`, `pane_id`, `session`), sorted by id, then by pane id (tmux's `%N` by number, so `%9` comes before `%10`) |
| `details` | optional, code-specific context |

`details` of `server_unavailable`: `socket_path`, plus `path` (the file or directory that failed) only when a socket safety check failed ([Server selection](#server-selection)); of `no_server`: `socket_path`; of `not_supported`: `placement` (the placement's name) and `fields` (what it uses that is not supported: `target` for `target: pane`, and each pane-only field it sets); of `config_invalid` from the environment: `variable`, from config: `key`.

|---|---|---|
| `usage` | 2 | all |
| `config_invalid` | 2 | all |
| `not_supported` | 2 | `open`, `placements` |
| `not_found` | 10 | every command that takes an id |
| `no_server` | 10 | every command that takes an id, except `exists` |
| `client_not_found` | 10 | `focus` |
| `vetoed` | 11 | `open`, `close` |
| `tmux_missing` | 12 | all except `placements` |
| `tmux_too_old` | 12 | all except `placements` |
| `server_unavailable` | 12 | all except `placements` |
| `command_not_found` | 12 | `open` |
| `tag_failed` | 12 | `open` |
| `no_client` | 12 | `focus` |
| `attach_failed` | 12 | `focus` |
| `locked` | 12 | `rename`, `mark`, `unmark`, `label add`, `label remove` |
| `state_changed` | 12 | `close` |

| `refused` | 20 | `close` |

**`locked` details.** `details` has `socket_path` and `cause`: `timeout` when another termctl held the lock for 10 seconds, or `unusable` when the state directory, a lock file or `flock` itself cannot be used ([Audit and log](#audit-and-log)); then `details` also has `problem` (e.g. `not owned by the current user`, `cannot lock: <reason>`) and, when one is known, `path`, and the message names both.

**tmux version.** Every command that talks to tmux runs `<tmux_bin> -V` before its first tmux operation and takes the first match of `\d+\.\d+` as the version; below 3.2 it exits 12 (`tmux_too_old`). Output with no such match is assumed new enough, with a warning. `tmux -V` exiting non-zero, timing out or printing more than 4096 bytes on stdout or on stderr exits 12 (`tmux_missing`). In `details` of both codes, `tmux_bin` is the configured value and `path` the absolute path it resolved to (absent when resolution failed); `tmux_too_old` adds `tmux_version`, the matched text.

## Hooks

Configured under `hooks` in config (design guide section 8: `cmd` run through `sh -c` in its own process group, JSON payload on stdin, timeout default 30 seconds, `async: true` allowed only on post-hooks, a config error on a pre-hook). Hooks run with the caller's full environment, not the filtered one, because they are the user's own configuration.

- **Execution.** termctl runs `/bin/sh -c <cmd>` (always that shell, whatever the `PATH`) in a new process group that it creates, and writes the payload to its stdin. A `cmd` must not contain a NUL character (a config error). A hook that does not read its stdin is not an error. No other descriptor of termctl's is inherited, and no hook runs while termctl holds the per-server lock ([Audit and log](#audit-and-log)). The group is a background process group (an async hook's is also in a session of its own), so a hook cannot use the controlling terminal: reading from it stops or fails the hook. A gate that needs a human escalates (exit 13) instead of prompting.
- **Wait.** termctl waits until the hook (the shell, the leader of the group) has exited and closed its stdout and stderr. If the hook exits while something it left behind still holds its stdout or stderr open, termctl keeps reading for at most 1 more second (never past the timeout), then stops reading and uses the hook's exit status; what the hook left behind is not signaled.
- **Timeout.** A `timeout` is a whole number of seconds from 1 to 600 (a larger one is a config error). When it passes before the hook has exited, termctl sends SIGKILL to the hook's process group and to the hook itself, while the hook is not yet reaped so that its PID cannot have been reused (never to any other process), and treats the hook as failed: a pre-hook timeout counts as a veto, its stdout is ignored and the stderr read so far is `hook_stderr`. A process the hook moved into another process group or session is not signaled. A hook that cannot be stopped even so (for example a set-user-ID program termctl may not signal) is reported as such and, for a pre-hook, counts as a veto.
- **Output.** termctl keeps the first 65536 bytes of a pre-hook's stdout and the first 4096 bytes of every hook's stderr, and reads and discards the rest, so a verbose hook is never blocked or killed for it. Post-hook stdout is discarded. Hook output never appears in a `message` or a warning; a hook's stderr is reported only as `hook_stderr` ([Errors](#errors)).
- **Pre-hook outcome.** Exit 0 allows; exit 13 escalates and later hooks still run; any other exit status, death by a signal, a timeout, or a hook that cannot be started vetoes and stops later hooks.
- **Post-hook failures** (a non-zero exit, a signal, a timeout, a failure to start) are a warning and a `hook_failed` log record, never an error. An `async: true` post-hook is started under a small watchdog (run as `python -I` with the absolute path of termctl's `hookwatch.py`, so the caller's current directory and `PYTHON*` variables cannot change its code, and it runs even where the interpreter cannot import termctl, such as a user-site install; it uses only the standard library) that termctl starts detached in a session of its own, with the payload on its stdin and its output discarded; termctl does not wait for it. The watchdog runs the hook in a process group of its own, hands the payload over unread, and enforces the hook's timeout as termctl does; if the watchdog itself gets SIGTERM, SIGHUP or SIGINT, it kills the hook the same way. An async hook's failure after it started is not reported.
- **`hook_failed` records** have `details` with `hook`, `cmd`, `problem` (termctl's own text, naming the problem without quoting hook output), `pgid` (the process group termctl created for the hook, or for an async hook the watchdog's; absent if the hook could not be started) and, when not empty, `hook_stderr` (**untrusted**, as in [Errors](#errors)). The log record of the `open` or `close` step lists the process groups of the hooks it ran.

`--hook NAME=CMD` (repeatable) adds a hook for one invocation, run after the configured ones. NAME must be one of that command's hooks (`pre-open` or `post-open` for `open`, `pre-close` or `post-close` for `close`; exit 2 otherwise); such a hook has the fixed 30-second timeout and is never async; a gate that needs longer belongs in config `hooks`. CMD must not be empty and must be valid Unicode text (exit 2 otherwise); it is split from NAME at the first `=`.

| Hook | Fires | Can veto/escalate | Payload |
|---|---|---|---|
| `pre-open` | after the tmux and id-collision checks (step 4 of [Open order](#open-order)), before tmux changes anything | yes | `schemas/hooks/pre-open.json`: the id to be assigned, name, cwd, argv, env variable **names** (never values), labels, placement, session, target, socket path, keep-on-exit, focus, `actor`, `decision_ids` (from `--decision-id`), `override_escalation` |
| `post-open` | after the pane exists (step 9) | no | `schemas/hooks/post-open.json`: the `open` output, under `pane` |
| `pre-close` | after the running check, before closing | yes | `schemas/hooks/pre-close.json`: the pane object under `pane`, `force`, `grace_ms`, `actor`, `decision_ids`, `override_escalation` |
| `post-close` | after the pane is gone | no | `schemas/hooks/post-close.json`: the close result, under `result` |

Every payload has the top-level fields `tool` (`termctl`), `hook`, `object_type` (`pane`), `object_id` (the termctl id) and `labels`; there is no `repo`. Payload strings are mapped like human output for undecodable bytes: a byte that was not valid UTF-8 (held as a lone surrogate, **Human output** in [Commands](#commands)) is the text `\xNN` and any other lone surrogate the text `\uXXXX`, so the payload is always valid JSON for a strict parser. The `pre-open` `object_id` belongs to one attempt: a re-run of the same `open` generates another id, so a gate correlates an override run with the escalated one by `decision_ids` and `actor`, not by id. Hooks receive `TERMCTL_HOOK`, `TERMCTL_ID` and `TERMCTL_OBJECT_TYPE=pane`. `rename`, `mark`, `unmark`, `focus` and label changes fire no hooks. Payload fields that termctl reads from a pane rather than from its own arguments (the `pane` object of `pre-close` and `post-open`, and the top-level `labels` of `pre-close`) are forgeable by anything with socket access ([Residual risks](#residual-risks)); a gate that must hold must not rely on them.

**Decision ids.** A decision id matches `^[A-Za-z0-9._:@/-]{1,128}$`, and a list holds at most 32. A `--decision-id` that breaks either rule exits 2. A `decision_id` (a string or a list) in a pre-hook's JSON stdout is collected, from every pre-hook that exited (vetoing and escalating ones included, and one killed by a signal other than termctl's timeout kill; not one that timed out); an id that is not a string, does not match the grammar, or would make the list longer than 32 is dropped. A hook whose ids are dropped gets one warning (and one `hook_failed` log record), which counts them and names the position and problem of the first, without quoting it. Stdout that is empty or only whitespace returns no ids; stdout that is not a single UTF-8 JSON object (a duplicate key and `NaN` or `Infinity` included), or that is longer than 65536 bytes, is ignored with a warning, and so is a `decision_id` that is neither a string, a list nor null. Ids are kept in the order the hooks returned them, duplicates included. Everywhere termctl reports `decision_ids` (the `open` and `close` output, the log record of the step, the error object of a veto or escalation) the list is the `--decision-id` values followed by the ids hooks returned; the audit record carries the same list under the design guide's field name `decision_id`.

**Escalation override.** termctl has no pending store and no `confirm` command (design guide section 4.4), so after a human accepts an escalation the caller recorded, the caller runs the same `open` or `close` again with `--override-escalation`. termctl is stateless and cannot know which hook escalated before, so it runs the pre-hooks as usual and treats exit 13 from any of them as allow; a veto still vetoes. Every pre-hook payload of such a run has `override_escalation: true`, so a policy can refuse override runs with a veto. The flag is accepted only when stdin is a TTY or with `--actor human:<user>` (exit 2 otherwise); automation never passes it on its own judgment. This gate is advisory ([Residual risks](#residual-risks)). The run is recorded in the log record and an audit record (`escalation_override`).

## Config

`~/.config/termctl/config.yaml` (respecting `XDG_CONFIG_HOME`) plus `config.d/*.yaml` in code point order, merged after it: maps are merged key by key at every depth, `hooks` lists are appended, and other lists (`server_env_allow`, `rules`) are replaced. Schema: `schemas/config.json`; every key with its default is in `config.example.yaml`. Invalid config exits 2 (`config_invalid`) naming the key (`details.key`). The key is a path in the merged config, so a list index in a `hooks` key counts in the appended list: the main file's entries first, then each drop-in's in order. Besides the schema, termctl checks at load that every rule names a defined placement, that `socket` is a socket name or an absolute path ([Server selection](#server-selection)), and that no pre-hook sets `async`. Unsupported placement fields are not a load error ([Placement](#placement)).

Config files are YAML, read with the YAML 1.2 core schema: the booleans are exactly `true`, `True`, `TRUE`, `false`, `False` and `FALSE`; null is exactly `~`, `null`, `Null`, `NULL` or an empty value; infinity and not-a-number are `.inf`, `.Inf`, `.INF` (with an optional `+` or `-`) and `.nan`, `.NaN`, `.NAN`. So `yes`, `no`, `on`, `off`, `tRuE`, `1:30`, `1_000` and `2024-01-01` are strings, `017` is 17, `0o17` is 15 and `0x1F` is 31. A YAML error or a violation of these restrictions exits 2 (`config_invalid`) with a one-line message naming the file (`details.file`), the line and column where the parser knows them (`details.line`, `details.column`), and the key where there is one:

- Every mapping key is a string and appears once in its mapping. Quote keys YAML reads as other types (`"true"`, `"null"`, numbers); a sequence or mapping key is not allowed.
- Anchors, aliases and merge keys (`<<`) are not allowed; config files need none, and aliases allow exponential growth.
- The only explicit tags are the core schema's: `!!str`, `!!seq`, `!!map`, `!!bool`, `!!int`, `!!float` and `!!null`; any other tag (`!!timestamp`, `!!binary`, `!!set`, a local `!tag`, the non-specific tag `!` or `!<!>`) is unsupported, on keys and values alike. A scalar tagged `!!bool`, `!!int`, `!!float` or `!!null` must have one of that type's forms above (`!!int 1_000` is an error). A tagged key is not a string unless the tag is `!!str`.

Two further checks apply to the merged config, so their errors name only the key (`details.key`), not a file, line or column: an integral float (`1.0`) is accepted where an integer is expected, as in the schema, but other floats are not; and every key and string must be valid Unicode, so one with a lone surrogate (from a `\u` escape) exits 2.

The main file may be missing (no settings), unless it was given with `--config` or it, or a directory above it, is a dangling symlink (the error names that symlink); any other failure to read it is an error. The main file and the drop-ins must be regular files after following symlinks; anything else (a directory, a FIFO, a device) is an error, and termctl never blocks opening one. The main file and each drop-in may be at most 1 MiB (1048576 bytes); a larger one is an error naming the file (`details.file`), and termctl reads at most one byte past the limit. A missing `config.d/` means no drop-ins; one that cannot be listed (unreadable, not a directory, a dangling symlink) is an error. Drop-ins are the entries whose names end in `.yaml` and do not start with `.`, read in code point order of their names. When neither an absolute `XDG_CONFIG_HOME` nor an absolute `HOME` is set, the home directory comes from the user's passwd entry; without one, or if it is not absolute, termctl exits 2 (`config_invalid`).

With `--config PATH`, termctl also reads the `config.d/` next to PATH. Drop-ins can add hooks, which run commands, so PATH should be a file in a directory only the user can write.

| Key | Default | Meaning |
|---|---|---|
| `backend` | `tmux` | terminal backend; `tmux` is the only one |
| `tmux_bin` | `tmux` | tmux executable; resolved once per invocation to an absolute path on the caller's `PATH` (if not already absolute) and used for every tmux call, including the `focus` attach argv |
| `socket` | `null` | default server ([Server selection](#server-selection)) |
| `server_env_allow` | `[PATH, HOME, USER, LOGNAME, SHELL, LANG, "LC_*", TERM, COLORTERM, TZ, "XDG_*", DISPLAY, WAYLAND_DISPLAY]` | variables kept in the environment termctl runs tmux with ([Environment](#environment)); entries are names or `PREFIX*` globs |
| `keep_on_exit` | `never` | [Command exit](#command-exit) |
| `close_grace` | `10s` | [`close`](#close); at most `10m` |
| `marker_display` | `name` | `name` or `option` ([Markers](#markers)) |
| `markers` | `{attention: {text: "🔔 ", bell: false}}` | marker definitions; merged with the built-in |
| `placements` | `{default: {session: termctl, target: window}}` | [Placement](#placement) |
| `rules` | `[]` | [Placement](#placement) |
| `hooks` | `{}` | [Hooks](#hooks) |

termctl has no per-repo overrides (it has no notion of a repository).

## Environment

- **Config from the environment:** `TERMCTL_<KEY>` sets a top-level scalar key (`TERMCTL_SOCKET`, `TERMCTL_TMUX_BIN`, `TERMCTL_BACKEND`, `TERMCTL_KEEP_ON_EXIT`, `TERMCTL_CLOSE_GRACE`, `TERMCTL_MARKER_DISPLAY`). An invalid value, including one that is not valid UTF-8, exits 2 (`config_invalid`) naming the variable. Other `TERMCTL_*` variables are ignored. Lists and maps (`server_env_allow`, `markers`, `placements`, `rules`, `hooks`) cannot be set from the environment. Precedence: flags > environment > config > built-in defaults.
- **Hook variables:** `TERMCTL_HOOK`, `TERMCTL_ID`, `TERMCTL_OBJECT_TYPE`; these are never config keys. Hooks get the caller's full environment ([Hooks](#hooks)).
- **The filtered environment:** termctl runs every tmux command with the caller's environment filtered by `server_env_allow` (the exceptions are the attach of [`focus`](#focus) and hooks). tmux takes several values from the environment of the process that runs a tmux command, so this filter decides them: the server's global environment when the command starts the server, the variables a new session imports (tmux's `update-environment`, e.g. `DISPLAY` and `SSH_AUTH_SOCK`), and the new pane's `PATH`. termctl therefore never adds the caller's credentials (for example from a cron env file) to tmux. A server started by anyone else keeps its own global environment.
- **Clients import their environment.** A client that attaches to a session or switches to it without `-E` (for example a user's plain `tmux attach`) imports its `update-environment` variables, such as `SSH_AUTH_SOCK`, into that session, and panes created there later get them (spike F1). termctl's own `attach` and `switch-client` always pass `-E`; what other clients do is outside termctl's control ([Residual risks](#residual-risks)).
- **`SSH_AUTH_SOCK`:** it is not in the default `server_env_allow`. When termctl creates a session, tmux marks every `update-environment` variable missing from the filtered environment as removed for that session, so no pane of that session (later windows included) gets `SSH_AUTH_SOCK`, even when the server's global environment has it, unless a client imports it as above. To keep it, add `SSH_AUTH_SOCK` to `server_env_allow` in user config, or have the caller provide it to the command (for example through agent-spawn's environment file).
- **`--env` scope:** `--env` variables reach only the new pane. tmux stores a `new-session -e` variable in the session environment, where later windows inherit it, while `new-window -e` and `respawn-pane -e` affect only the pane (spike G). So with argv only `respawn-pane` gets `-e` (the placeholder gets none); without argv `new-window` gets `-e` in an existing session, and `new-session` gets `-e` chained with `set-environment -t '=<session>:' -u K` for each variable `K`, so only the first pane keeps them ([Open order](#open-order) step 5). A variable named twice exits 2.
- **The command's environment:** a pane gets the server's global environment as modified by its session's environment (which may remove or add variables, above), `PATH` from the filtered environment (or `--env PATH`, [Command](#command)), and the `--env` variables; not the rest of the caller's environment. tmux also sets `TMUX` and `TMUX_PANE` in every pane.
- termctl reads no credentials.

## Audit and log

- `log.jsonl` (`schemas/log.json`) in `~/.local/state/termctl/` (respecting `XDG_STATE_HOME`): one record for every invocation of `open`, `close`, `rename`, `mark`, `unmark`, `label add`, `label remove` and `focus` that got past the usage check ([Check order](#check-order) step 1), failures included (exit 10, 11, 12, 13, 20, 21, and the exit 2 of a label limit checked after id resolution), but not dry runs or no-ops. Fields: `ts`, `level`, `event`, `id` (null if none was resolved), `socket_path` (null if none was resolved), `result` (`ok`, `error`, `vetoed`, `escalated`, `refused` or `warning`) and, when known, `exit_code`, `message` and `details` (code-specific context). `event` is the command (`open`, `close`, `rename`, `mark`, `unmark`, `label_add`, `label_remove` or `focus`), or `hook_failed` or `warning` for the records that warnings and hook failures get of their own, with `result: warning`. `level` is `error` for `result: error`, `warn` for `warning`, `refused`, `vetoed` and `escalated`, else `info`. `open` and `close` records always carry `actor`, `decision_ids` and `escalation_override`, and no other record carries `actor` or `escalation_override`; `close` records carry `force`; `focus` records carry `action` (`switched` or `attach`; an attach is logged before the exec). An `open` that ends in `tag_failed` is logged with `result: error`.
- `audit.jsonl` (`schemas/audit.json`): one record for every `close --force` in which step 1 or step 3 of [`close`](#close) saw a running pane, whatever its outcome, and for every `open` or `close` run with `--override-escalation`. A record is written only once the id exists: generated (`open`, step 2 of [Open order](#open-order)) or resolved (`close`); a failure before that is only logged. Fields: `ts`, `actor`, `decision_id` (the same list as `decision_ids` elsewhere, under the design guide's field name, section 6), `target` (the id), `action` (`open` or `close`), `force`, `escalation_override`, `inputs`, and `result` (the `--json` output, or the error object). `inputs` has `socket_path`, `pid` (the recorded PID) and `grace_ms` (null unless forced); for `open` it also has `name`, `argv`, `cwd`, `placement`, `session`, `env_names` and `labels`, and `pid` and `grace_ms` are null. termctl takes no other action the architecture counts as external.
- **Actor.** `--actor` matches `^(human|auto):[A-Za-z0-9._@-]{1,64}$` (exit 2 otherwise). The default, when stdin is a TTY, is `human:<OS user name>` if that name fits the grammar and `human:unknown` (with a warning) if not; otherwise it is `auto:unknown` (termctl has no `me` config).
- **Records.** Each record is one line, written with a single append. A write cut short (disk full) can leave a partial line, which the next record never joins; readers skip lines that do not parse.
- **Locking.** `rename`, `mark`, `unmark`, `label add` and `label remove` read and rewrite pane options; each holds an exclusive `flock` on `locks/<first 16 hex digits of sha256(socket_path)>.lock` in the state directory while it does. termctl waits at most 10 seconds for the lock, then exits 12 (`locked`, `details.cause: timeout`). A state directory, lock file or `flock` that cannot be used also exits 12 (`locked`, `details.cause: unusable`, with `path` and `problem`; see [Errors](#errors)). The lock is never held while hooks run, and the kernel releases it if termctl dies. termctl never deletes lock files.
- **State directory.** It holds only these two files and `locks/`. termctl creates the state directory, `locks/` and missing parent directories with mode 0700 and files with mode 0600, whatever the umask; when it must create a directory, the nearest existing parent must be owned by the current (effective) user, else termctl refuses (problem `parent <path> not owned by the current user`), so root under `sudo -E` never creates directories in a user's home. termctl refuses the state directory, `locks/`, `log.jsonl`, `audit.jsonl` or a lock file that is not owned by the current user, is writable by group or others (also for a user-private group: on macOS the primary group `staff` holds every local user), is a symlink (the state directory itself may be a symlink to a directory that passes these checks), is not a directory (`locks/`, the state directory) or regular file (the others), or, for a file, has more than one hard link. Every check is made on the opened descriptor. The error names the path and the problem (with the mode when the entry is writable by group or others) and suggests `chmod go-w '<path>'` where that fixes it. Existing parent directories are not checked, and macOS extended ACLs are not checked.

## Residual risks

- **The tmux socket is full control.** Any process that can reach the server's socket (every process in its panes, through `TMUX`) can open, rename, close and read any window, including changing termctl's pane options and window names (so `display_name` is untrusted). termctl cannot prevent this; sessions that read third-party content must not reach the socket, which claude-session's sandbox enforces (architecture section 13.1).
- **Forged options.** Anything with socket access can write `@termctl_*` options that make a pane look managed, at pane scope or at window, session or global scope with `@termctl_pane` naming the pane; set a global `@termctl_pane` so that every `open` fails its tagging guard with `tag_failed`; or install server hooks whose output (for example an `after-list-panes` hook's) forges whole `list-panes` records, since a hook can see the read's format and its per-read sentinel.
- **Forged control bytes.** termctl checks a pane option's value as tmux prints it, and tmux prints a C0 or DEL byte, or a byte that is not valid UTF-8, in a user option as backslash escape text (`\033` for ESC, `\177` for DEL, `\377`, `\r`). Such a forged byte is therefore not rejected: a name set to `n`, ESC, `[2Jx` reads as the text `n\033[2Jx`, which cannot be told from a name containing that literal backslash text. No raw control character reaches termctl's output. A C1 character written as UTF-8, and a newline, are rejected as invalid values.
- **Human gates are advisory.** `--override-escalation` and `close --force` require a TTY on stdin or `--actor human:<user>`, but every pane has a TTY and `--actor` is self-declared. The gates stop automation that follows the rules, not a hostile caller; policies that must hold use a pre-hook veto, which an override never bypasses.
- **Clients import their environment.** A user's plain `tmux attach` or `switch-client` imports variables such as `SSH_AUTH_SOCK` into a session termctl created, and later panes there get them ([Environment](#environment)).
- **`exit-unattached` on servers termctl starts.** termctl turns `exit-unattached` off on a server it starts, overriding a user's `exit-unattached on` for that server; it never changes a server it did not start, except in the short race where another server starts between `open`'s last socket check and its server start ([Open order](#open-order) step 5).
- **Socket path races.** A component of the socket path may change between termctl's checks and tmux's connect. After the checks only the real uid or root can replace a checked component, so the window is not exploitable by other users; a *no server* result is never followed by a connect without re-running the checks.
- **Orphans after `close --force`.** Only the recorded process is signaled, by PID, never a process group; its children get only the kernel's SIGHUP. Children that ignore SIGHUP, or that the command moved into another session or process group, survive.
- **`--env` values are visible** to local process listings while the tmux client runs.
- **Restored windows.** Tools that recreate windows after a tmux server restart do not restore termctl's options; such windows are unmanaged.

## Platform notes

- tmux 3.2 or newer. `exit_signal` needs tmux 3.3 (verified on 3.5; 3.3 and 3.4 unverified); on tmux 3.2 a dead pane can have both exit fields null ([Command exit](#command-exit)).
- Linux and WSL are supported. macOS is supported best-effort (architecture constraint C4 requires termctl on macOS only for interactive use); process start times there have one-second resolution.
- Socket paths are limited to 100 bytes.
- Marker texts display as the terminal and locale allow; under a non-UTF-8 locale the built-in `🔔` may not render, and ASCII marker texts are the fallback.
